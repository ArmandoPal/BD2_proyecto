\section{Organización de archivos}
\subsection{Heap y Free-List}
La metadata del Heap contiene el tamaño de registro, cantidad de filas y \texttt{free\_head}. Esta cabecera apunta a la primera página que dispone de slots. Cada página libre enlaza la siguiente mediante \texttt{next\_page\_id}. Insertar lee únicamente la cabecera conocida de la lista y su primera página, o anexa una página nueva: el costo de I/O de la organización es constante. La comprobación de unicidad y el mantenimiento de índices son costos adicionales del ejecutor.

La eliminación es lógica mediante el bitmap. Si una página antes llena recupera un slot, se añade a la lista libre. El escaneo recorre todas las páginas de datos, con una lectura por página, y devuelve solamente slots activos.

\subsection{Sequential, overflow y reorganización}
Las páginas principales y sus registros activos están ordenados por la clave primaria. Cada página persiste una frontera inferior que no cambia al borrar registros; esto permite buscar páginas mediante búsqueda binaria incluso si una página queda vacía. Insertar ocupa un slot únicamente cuando preserva el orden físico sin desplazar RID. Las inserciones ascendentes pueden anexar nuevas páginas.

Cuando no hay un hueco apropiado, el registro se inserta en una lista de overflow ordenada, cuya cabeza pertenece a la página principal correspondiente. Cada registro de overflow almacena el RID siguiente. \texttt{OverflowManager} reutiliza un Heap para asignar slots, pero el orden lógico reside en los enlaces binarios, no en una lista en RAM.

\texttt{reorganize()} recorre las páginas principales y sus cadenas, fusiona ambos flujos ordenados y escribe un archivo principal temporal. Llena cada página hasta aproximadamente 75\% (redondeado hacia abajo), reemplaza el principal y reinicia el overflow. Conserva solo páginas y cursores en memoria. El ejecutor reconstruye todos los índices, incluido el de integridad de la clave primaria, porque los RID cambian durante esta operación.

Un overflow muy largo incrementa el costo de inserción y búsqueda. La reorganización es mantenimiento explícito mediante API o Python; no hay un planificador periódico automático. No se requiere ordenar toda la tabla en memoria para reorganizarla.
