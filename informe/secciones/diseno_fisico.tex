\section{Diseño físico y medición}
\subsection{Page Layout y RID}
Toda transferencia binaria pasa por \texttt{DiskManager}. Los tamaños permitidos son 1024, 2048, 4096 y 8192 bytes, con 4096 por defecto. El desplazamiento físico de una página se calcula como:
\[\text{offset}=\text{page\_id}\times\text{page\_size}.\]
La cabecera común ocupa 20 bytes y contiene identificador, número de registros, offset libre y enlaces siguiente/anterior. En páginas de registros se agregan 12 bytes de configuración, metadata opcional, un byte de presencia por slot y los registros de longitud fija. Si $m$ es la metadata adicional y $r$ el tamaño del registro, la capacidad es:
\[C=\left\lfloor\frac{B-20-12-m}{r+1}\right\rfloor.\]
Para productos en Heap, $B=4096$, $r=394$, $m=0$: caben diez registros por página. El primer registro comienza en el byte 42. La página cero contiene metadata del archivo y no forma parte de las filas de la tabla.

El RID es el par \texttt{(page\_id, slot\_number)}. Las eliminaciones liberan slots sin mover otros registros. Para distinguir el overflow del Sequential dentro del mismo espacio lógico de RID, una página de overflow $p$ se codifica como $-p-1$; los identificadores físicos de sus archivos siguen siendo positivos.

\subsection{Serialización y contador}
\texttt{RecordSerializer} usa enteros y flotantes de 64 bits en formato little-endian, y CHAR de longitud fija en bytes UTF-8. Rechaza valores de tipo incorrecto, texto demasiado largo, caracteres NUL y flotantes no finitos.

\texttt{DiskCounter} incrementa una lectura después de una transferencia completa de página y una escritura después de una escritura completa, incluida la asignación inicial. No se usan fórmulas para fabricar estas métricas. El contador se reinicia por consulta e incluye las páginas de metadata abiertas por el ejecutor. El catálogo JSON es metadata administrativa y no entra en el contador de páginas.

El archivo se abre sin buffering de Python. Las cifras cuentan transferencias solicitadas al archivo, no fallos de caché del sistema operativo ni accesos mecánicos del dispositivo. El SO puede retener páginas; no se fuerza caché fría ni \texttt{fsync} por operación. Para recuperar varios RID, el ejecutor retiene como máximo 32 páginas de datos por consulta; las consultas comienzan sin ese buffer.
